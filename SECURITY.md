# Проверка защиты учётных данных — 8 ноября 2026

Обновление 0.3.3: шифрование и расшифровка сессии переведены на асинхронный safeStorage с таймаутом, без синхронного fallback. Новый файл — `session-v2.enc`; выход удаляет и его, и старый `session.enc`. Режим совместимости Gamescope не отключает песочницу. Диагностика старта записывает только фиксированные этапы, режим графики и коды завершения, без токенов, URL, аргументов, окружения и текстов исключений.

Проверены исходники основного процесса, preload, интерфейс, CSP, сетевые адреса и состав упаковки. Использовались только синтетические токены. Реальные учётные данные пользователя не запрашивались, не читались и не отправлялись. Это проверка кода и локальные тесты, не независимый пентест.

## Найдено и исправлено

- Введённый вручную токен оставался в DOM после ошибки/закрытия окна. Теперь поле очищается сразу после передачи в IPC и при закрытии. При ручном вводе токен неизбежно кратковременно доступен renderer; рекомендуемый способ — Device Flow, где access token не попадает в renderer.
- Произвольные сообщения исключений и ответов API пересылались в UI. Некоторые технические ошибки могли содержать чувствительные параметры. Теперь через IPC возвращаются только контролируемые сообщения приложения; нативные ошибки заменяются общей строкой, серверные сообщения не отражаются.
- Fetch использовал автоматические редиректы. Это не доказанная отправка Authorization стороннему хосту: поведение зависит от типа перенаправления. Теперь все запросы с токенами/кодами используют `redirect: 'error'`, разрешены точный origin музыкального API и два точных OAuth endpoint. Музыкальный Authorization не добавляется к OAuth-запросам. CDN-запросы выполняются без Authorization.
- Незавершённый вход мог завершиться после отмены или выхода, заново установив токен. Теперь проверяется поколение авторизации, а операции записи/удаления файла сессии упорядочены.
- Ответ аккаунта передавался в UI целиком. Теперь разрешены только uid, login, displayName.
- Поле trackCount вставлялось в HTML без экранирования. Добавлено экранирование. Названия и исполнители уже экранировались; CSP запрещает inline script и внешние скрипты.

## Что защищено

- Пароль Яндекса не запрашивается. Device Flow использует сайт Яндекса на телефоне/внешнем браузере.
- Пользовательский токен не включается в URL, исходники, логи или localStorage; там сохраняется только громкость. В сборку включены electron/, ui/ и package.json, не профиль пользователя.
- Сохранение токена — через safeStorage. На Linux при `basic_text` запись запрещена. При других backend гарантии зависят от системного хранилища. На Windows DPAPI не защищает от другого процесса, запущенного от того же пользователя: https://www.electronjs.org/docs/latest/api/safe-storage
- Renderer: sandbox, contextIsolation, nodeIntegration=false; фиксированный список IPC и проверка отправителя/главного frame. Произвольных сетевых/файловых IPC нет. Навигация и новые окна запрещены.
- client_id/client_secret Android-клиента в исходниках — публичные общие идентификаторы стороннего OAuth-клиента, не персональные данные. Desktop-сборка не может скрыть такой secret. Это зависимость от неофициального сценария авторизации, не собственный конфиденциальный OAuth-клиент.

## Остающиеся риски

- Захваченный bearer token позволяет действовать в пределах его прав до отзыва. Приложение не гарантирует ограничение токена только музыкой.
- Вредоносное ПО/отладчик с доступом к процессу, пользовательскому профилю или root может получить токен из памяти либо системного хранилища. JavaScript не даёт надёжного обнуления строк в памяти; дампы памяти также чувствительны.
- Заражённая сборочная машина, подмена неподписанного приложения и уязвимости Electron/зависимостей остаются за пределами защиты токена в коде. Windows-сборка не подписана. Сборщик имеет отдельные moderate предупреждения npm audit; production audit не выявил уязвимостей на момент проверки.
- Без реального Steam Deck не проверены конкретный backend keyring и поведение при разблокировке/блокировке SteamOS. Нельзя обещать отсутствие утечек при компрометации ОС или Яндекса.

## Проверки

`node --test`: авторизация, изоляция адресов, запрет редиректов, отсутствие токена в OAuth Authorization, фильтрация ошибок, гонки отмены/выхода и минимизация ответа аккаунта. `npm run test:ui`: запуск, IPC, изоляция Node.js, окна и очистка поля токена. Все секреты в тестах синтетические.
