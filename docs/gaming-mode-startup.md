# Gaming Mode: запуск и диагностика — 0.3.4

В 0.3.4 исправлен обнаруженный по журналу сбой `GPU process launch failed: error_code=1002`, приводивший к завершению с кодом 133. Пользователь подтвердил успешный запуск исправленного варианта в Gaming Mode на Steam Deck OLED. Это подтверждение запуска на конкретном устройстве, а не проверка всех функций на всех моделях Deck.

## Что попробовать

1. Полностью закройте предыдущий Yamu. Распакуйте новую Linux-сборку в отдельную постоянную папку.
2. В Desktop Mode разрешите исполнение скриптов:

   ```sh
   chmod +x start-yamu.sh start-yamu-gamemode.sh
   ```

3. В свойствах ярлыка Steam укажите **`start-yamu-gamemode.sh` из новой папки**. «Рабочая папка» / Start In — та же папка. Старый ярлык на бинарный файл из предыдущего архива не обновляется автоматически.
4. В совместимости Steam отключите принудительный запуск через Proton/Steam Linux Runtime. Используйте нативный скрипт; не запускайте от root.
5. Перейдите в Gaming Mode и запустите ярлык. Для Desktop Mode используйте обычный `start-yamu.sh`.

Для AppImage передайте `--steam-deck --fullscreen` в параметрах запуска Steam. Это включает тот же режим совместимости внутри приложения. В окружении, где определён Gamescope, обычный скрипт также выбирает его автоматически.

Временная проверка старой сборки: параметры `--ozone-platform=x11 --disable-gpu --in-process-gpu --fullscreen` у ярлыка на обычный скрипт. Они не заменяют исправление работы с хранилищем в 0.3.4.

## Изменения

- Gaming Mode использует X11/XWayland вместо автоматического выбора Wayland и программную отрисовку вместо GPU. Графическая служба переносится в основной процесс через `--in-process-gpu`, теряя отдельную процессную изоляцию; песочница renderer, context isolation и запрет Node.js в интерфейсе сохраняются. Это действует и для AppImage с `--steam-deck`.
- X11 выбирается до создания окна. Desktop Mode сохраняет стандартное поведение.
- Вход больше не вызывает синхронные методы шифрования Electron. Проверка доступности, шифрование и расшифровка выполняются асинхронно с таймаутом 5 секунд на операцию.
- Если хранилище недоступно, интерфейс остаётся отзывчивым и позволяет войти через код устройства. В таком случае сессия действует до закрытия приложения. Незащищённый Linux fallback не используется для записи токена.
- Новая сессия сохраняется в `session-v2.enc`. Старый `session.enc` читается через асинхронный API при наличии подходящего хранилища. Выход удаляет оба файла; автоматически удалять старую сессию для запуска не нужно.

Обычный скрипт с `--steam-deck --enable-gpu` позволяет отдельно проверить аппаратную отрисовку. `--desktop-mode` отключает автоопределение режима Gaming Mode. Не используйте `--no-sandbox` и не меняйте права системных файлов для обхода ошибки запуска.

## Если по-прежнему вылетает или зависает

После неудачного запуска вернитесь в Desktop Mode и сохраните:

- `~/.local/state/yamu/launcher.log` (или `$XDG_STATE_HOME/yamu/launcher.log`) — старт скрипта и код завершения бинарного файла.
- `startup.log` в пользовательской папке Yamu внутри `~/.config/` — этапы `main-start`, `app-ready`, `window-created`, `ui-loaded`, восстановление сессии и коды выхода дочерних процессов. Найти файл можно через Dolphin поиском `startup.log`.

Эти журналы содержат фиксированные этапы, настройки режима и коды ошибок; аргументы командной строки, URL, переменные окружения, токены и тексты исключений в них не записываются. Каждый новый запуск заменяет предыдущий журнал. Скопируйте файлы после сбоя до следующего запуска.

Сообщите версию SteamOS, выбранный файл ярлыка и приложите оба журнала. **Не прикладывайте `session.enc` и `session-v2.enc`.**

## Проверки

Добавлены тесты определения Gamescope, явного режима совместимости, настроек графики, таймаута хранилища и запрета plaintext fallback. На Windows проверены асинхронный цикл шифрования/расшифровки, чтение старого зашифрованного формата на синтетических данных и существующие сценарии Electron. Linux CI запускает тесты MPRIS, синтаксиса shell-скриптов и окна Electron под Xvfb, затем собирает Linux-архив и AppImage. Успешный запуск исправленного варианта в Gamescope подтверждён пользователем на Steam Deck OLED; полная проверка всех функций остаётся отдельной задачей.

Скрипт `diagnose-yamu-gamemode.sh` включён в архив. При проблемах запустите его из Steam и сохраните очищенный `~/.local/state/yamu/gamemode-diagnostic.log`. [Подробности диагностики](gamemode-diagnostic-launcher.md).

Основания: [параметры Electron](https://www.electronjs.org/docs/latest/api/command-line-switches), [safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage).
