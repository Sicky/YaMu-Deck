# Исправление воспроизведения 0.1.1

Сообщение «Некорректные данные аудио» на скриншоте выдавалось в directLink: код ожидал исключительно XML и десятичное поле ts. Поле ts в данных Яндекса может быть шестнадцатеричным; такой пример есть в [тестах открытого клиента](https://github.com/MarshalX/yandex-music-api/blob/main/tests/test_download_info.py). Точный ответ аккаунта пользователя не читался, поэтому конкретный вариант сбоя на его сессии не установлен.

Теперь поддерживаются XML/JSON и hex/decimal ts без преобразования регистра или значения при формировании подписанной ссылки. Добавлена проверка типов полей, ограничение размера метаданных, обработка XML-сущностей и более конкретные безопасные ошибки. Ответ API без массива вариантов больше не приводит к вызову filter у объекта.

Сохраняются HTTPS, проверка адресов Яндекса, запрет редиректов запросов метаданных и отсутствие Authorization при запросах CDN. Реальный токен и подписанные аудиоссылки не запрашивались и не логировались.

Регрессии проверены синтетическими XML/JSON, включая весь путь stream → CDN metadata → MP3 URL, неправильные адреса и неверные поля. Проверка реального воспроизведения с пользовательским аккаунтом остаётся необходимой.
