# Диагностика до загрузки Electron

Если в launcher.log есть новый launcher-start, но startup.log относится к более раннему Desktop-запуску, последний startup.log не доказывает прохождение запуска в Gaming Mode. Нужны вывод нативного процесса и согласованный по времени журнал. Возможна также запись startup.log в другую папку профиля.

Для существующей Linux-сборки 0.3.3 не требуется переустановка:

1. Скопируйте [diagnose-yamu-gamemode.sh](../scripts/diagnose-yamu-gamemode.sh) в папку, где находится бинарный файл `yamu` (рядом с обычными скриптами запуска).
2. Разрешите исполнение: `chmod +x diagnose-yamu-gamemode.sh`.
3. Укажите этот скрипт целью ярлыка Steam, а его папку — Start In. Принудительная совместимость с Proton/Steam Linux Runtime должна быть выключена.
4. Запустите ярлык в Gaming Mode. Если логотип остаётся, подождите хотя бы 15 секунд, затем завершите приложение через Steam.
5. Вернитесь в Desktop Mode и сохраните `~/.local/state/yamu/gamemode-diagnostic.log` (либо `$XDG_STATE_HOME/yamu/gamemode-diagnostic.log`).

Диагностический вариант v2, включённый в сборку 0.3.4, задаёт X11, программную отрисовку и `--in-process-gpu` прямо в командной строке до исполнения кода приложения. Это проверяемый обход обнаруженной в Gaming Mode ошибки `GPU process launch failed: error_code=1002`, за которой следует `GPU process isn't usable` и завершение с кодом 133. Причина невозможности запуска дочернего процесса из этого журнала не устанавливается; предупреждение о 32-битной библиотеке Steam само по себе не доказывает причину сбоя.

Согласно [исходному коду Chromium](https://github.com/chromium/chromium/blob/main/content/public/common/content_switches.cc), `--in-process-gpu` переносит графическую службу в поток основного процесса. Изоляция этой службы отдельным процессом теряется; песочница renderer и изоляция Node остаются включены. `--no-sandbox`, `--disable-gpu-sandbox` и `--single-process` не используются. ELECTRON_RUN_AS_NODE убирается только у запускаемого процесса; системные настройки не изменяются. Пользователь подтвердил успешный запуск этого варианта в Gaming Mode на Steam Deck OLED.

В журнал записывается присутствие нескольких переменных, без их значений, состояние процесса через 8 секунд и код завершения. Нативный stdout/stderr очищается в памяти: строки с заголовками авторизации, cookie, OAuth/токенами и паролями скрываются, URL и длинные значения удаляются. Необработанный вывод на диск не записывается; подробное Chromium logging не включается.

Если приложение откроется через этот скрипт, сообщите об этом: это отличает проблему ранних параметров запуска от последующего зависания. Если нет — приложите новый диагностический журнал. Файлы сессии не нужны.
